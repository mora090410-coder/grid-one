# GridOne engineering release preflight

Use this checklist for a free-only GridOne release. Local validation is not production evidence; verify the deployed SHA and relevant runtime contracts separately.

## Preconditions and evidence custody

Record exact branch/commit, operator, environment and check URLs. Never paste secrets, bearer links, purchaser names/emails, Stripe payloads or payment credentials into reports. Use isolated fixtures/test-mode mocks for engineering checks. Preserve production backup and a reviewed rollback decision before any separately authorized migration. Main is Git-connected to production; merging is a deployment action, not just repository housekeeping.

Required engineering gates: focused regressions, typecheck, full unit suite, build, design lint, full disposable-Postgres integrations, Chromium, rendered phone/desktop and keyboard/a11y inspection, dependency audit review. A Docker startup error is not SQL test evidence. A missing browser executable is not a product UI failure. CI must run the real integrations; never substitute static SQL scans or model output. Keep full warnings and failures.

## Database/deployment order — separate operator approval required

1. Inventory hosted migrations/functions/triggers/effective grants and compare with the reviewed candidate. Preserve intentional missing 004. Do not assume repository history represents hosted state.
2. Verify backup/recovery and apply missing reviewed migrations in numeric order. Both 035 and 036 are mandatory, then 037 and 038; never apply 036 instead of 035. 037 uses an exact prerequisite check and must abort on mismatch; do not remove that guard to force deployment.
3. Independently verify effective EXECUTE for PUBLIC, anon, authenticated and service_role. Internal definer functions must deny API roles, legacy lease v1 must be absent, required service RPCs must remain available, owner rename/owns RPCs must work, and authenticated contest updates must be board_data-only. Check table AND column grants/default privileges, denial of non-owner and direct locked-state writes, normalized writes, cross-account denial, legitimate draft create/save/delete, sharing, publication, owner corrections, service score lease and snapshot access. Do not widen grants for test convenience.
4. Seller POST protection reuses server-only GUEST_INVITE_SECRET (at least 32 characters) and existing guest rate buckets. Verify configuration without exposing/changing its value here. Missing configuration or RPC failures intentionally close claiming. Confirm CF-Connecting-IP comes from the trusted Cloudflare edge. Fixed-minute limits: 20 requests/IP and 30/link; at most 10 squares/request. Not a per-person quota; boundary bursts/distributed abuse remain possible. Verify throttling does not corrupt a claim and normal sharing still works. Do not advertise abuse elimination.
5. Verify hosted migration 037 with Mora/Mora, whitespace/case/NFKC variants, distinct identifying names, concurrency, other-seller scope, revocation, locks and quarter-number boards. Recover mistakes before number lock: rotate an abused link, reload current board/revision, identify exact square, restore displayed seller label through the normal owner save, retain responsibility, separately review private payment notes, reload and verify availability. Never reset the entire board or treat a claim as payment. Do not silently alter finalized results.

## Auth and browser release gates — UNVERIFIED

Verify Supabase confirmation policy, SMTP sender/domain and provider restrictions with authorized operator access. Verify exact reset redirect allowlist for https://www.getgridone.com/reset-password and https://getgridone.com/reset-password, confirmation return behavior, root recovery versus reset route, expired/invalid/reused links, existing session and cross-tab/device behavior. Send only separately approved messages to consenting external test recipients and verify actual inbox delivery, not just API acceptance. Confirm signup -> save -> share -> finalize and forgotten password -> usable reset -> sign-in. Inspect phone and desktop, keyboard focus/escape/return, field-linked errors, selected-square changes, blank refusal versus deliberate clear, paid reset, pending-save unload and conflict/reload. Browser keepalive is best effort; it cannot guarantee delivery after process/network termination, especially while another request is already in flight.

Engineering recovery behavior: only a verified Supabase PASSWORD_RECOVERY event bound to the exact user/access-token session authorizes password reset; a URL or cached ordinary sign-in does not. Recovery arrival gets a 500ms disabled-form grace for the SDK's delayed event, never URL-derived authority. Draft edits committed to the workspace are copied synchronously into owner+board-scoped sessionStorage, with a 24-hour logical expiry checked on read. This is same-tab browser-session recovery, not server durability or survival of tab closure/storage clearing. A recovered copy requires explicit save or discard/reload and does not automatically publish. Title input commits on blur/Enter; uncommitted control text is not covered. Copies can contain board participant names; keep them local, out of logs/analytics and receipts. Storage failure must show a warning rather than promise recovery. Server acknowledgements may delete only the matching saved copy, not a newer edit; successful external-field saves must refresh any remaining recovery copy.

Browser export acceptance explicitly uses a shared 15-second artifact-completion budget for download and the native-share test receiver. Reproduction produced valid PNG bytes just after the native test's former default five-second polling deadline; this is a test-budget correction, not a certified image-export speed improvement. PNG type, nonempty file, eight-byte PNG signature, quarter footer and viewer/a11y assertions remain required. The native receiver is mocked and does not certify a physical OS share sheet or message delivery.

## Game-day operational gates — UNVERIFIED

Inventory site/API and separately deployed score-refresh and notification-retry Workers. Verify schedules, endpoint URLs, cron authentication, LIVE_SCORING_ENABLED and retry behavior without logging secret values. Verify upcoming NFL schedule creation and provider outage behavior; automatic score recovery does not recover missing schedules. Obtain commercial provider rights/usage/cost confirmation rather than assuming public endpoint access permits commercial use.

Observe a complete live game against a trusted source: correct matchup, kickoff, explicit zero versus unknown quarters, halftime, Q1/Q2/Q3/Final, overtime included in Final, per-quarter axes, OPEN/no rollover/no winner mail. Force a controlled provider outage and manual override, reject pre-kickoff/manual missing-kickoff writes, verify late/stale auto never wins and deliberate return to automatic works. Check rename before resolution synchronizes identity, after resolution freezes it, correction is audited/viewer-visible and quiet correction sends no unintended mail. Test verified opt-in, scanner-safe verification/unsubscribe, one winner notification, retries/leases/idempotency, bounce/error visibility and actual inbox receipt under separate message approval. Record observed times; a fetched-at stamp is not independently certified event freshness.

## Billing retirement safety

- Inventory only GridOne-specific live and test products, checkout sessions, webhook destinations, and historical obligations. Treat an empty dashboard filter as inconclusive until the account and environment are confirmed. Do not presume there are no purchases, refunds or disputes.
- Verify that application checkout creation is disabled and the exact release is live before retiring its provider configuration. Keep the rollback route from reactivating checkout. Do not delete financial history or disable webhooks needed for unresolved historical settlement.
- Only with the applicable owner approval and after resolving outstanding activity, retire GridOne-specific checkout assets and environment bindings. Keep shared credentials, unrelated products, score refresh, notification retry, auth, and abuse controls untouched. Do not write secret values into evidence.

Apply the reviewed migration 041 before the matching free-only application is deployed. That release retires the billing routes, including the old webhook, so prior settlement must be independently cleared **before** application cutover. Verify publication and scoring on synthetic fixtures, and confirm the deployed exact SHA before removing inactive Stripe-only bindings.

## Rollback / stop

Stop rollout or outreach on privacy, duplicate-claim, wrong-winner, grant-bypass or unexpected payment evidence. Keep published boards readable and manual score authority available. Disable affected paths with existing authorized controls; do not delete boards, roll back security grants, drop migrations or rewrite audit/history. App rollback must retain schema-compatible code and must not re-enable the original seller collision. Prefer reviewed corrective forward migrations; production SQL and worker changes require separate approval. Preserve canonical orders and event IDs for reconciliation; never automatically issue refunds from this runbook.

Demand remains unverified and cannot be fixed in code. Use the consented pilot template only after readiness and separate outreach approval.
